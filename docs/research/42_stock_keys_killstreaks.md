The inventory table (`10_iw8_entity_inventory.md` lines 35-69) matches. Missing only on worldspawn and collmap_scriptable, plus a few one-offs.

### 2.2 What it does (UNVERIFIED)

- Key table: `footprint_mask_group` is id 20186 (`iw8_canonical_keys.tsv` line 18879). Neighbours are `footprint_mask_enable` (20185, line 18878), `fnfootprinteffect` (20021, line 18714), and `flirfootprints` (19913, line 18606). The group is probably a named mask set for ground footprint decals (snow or mud footprints) that a volume or entity selects.
- No reader found: x64-zt `src` has no `footprint_mask_group` string. The only `footprint_mask_*` in x64-zt is a GSC token `footprint_mask_clipheight` (`games\iw8\assets\gsc_tool_iw8_tokens.inc:4167`), a different key. ACTS `src` has no hits.
- Editor treats it as a plain string: `src\core\trigger_templates.cpp:72-157` adds `default` to trigger templates, `src\core\scripted_objects.cpp:31` and `:58` add `default` on make-destructible and make-scripted, and `tests\scripted_objects_tests.cpp:37` checks it.

### 2.3 Converter path (VERIFIED for resolution)

- x64-zt writes key names as numeric ids through `iw3KeyToIw8KeyId` (`maps.cpp:25`), which uses `FindOpaqueString`. Unresolved keys are dropped and counted in `unnamedKeys` (`maps.cpp:685`).
- The lookup is FNV-1a 64 over the lowercase key (`replay_opaque_strings.cpp:21-36`). `footprint_mask_group` hashes to `9e982d470284cf89`, which maps to id `0x00004EDA` (20186) in `replay_opaque_strings.inc`. It resolves, so the key is kept.
- Caveat: that lookup is for keys from the IW3-style source path. Whether the editor's own `.ents` text reaches that path unchanged is not checked in this pass.

### 2.4 Safe default for editor-made entities (VERIFIED for stock, recommendation)

- Use `footprint_mask_group default` on every class that carries it in stock. This matches 3225/3225 and 603/603 stock values, and the editor already does this for several classes.
- Omitting it is probably harmless (worldspawn and collmap do not carry it), but writing `default` keeps parity with stock.

### 4.2 What the editor shows (VERIFIED)

- `src\core\map_text.cpp:169-177`: `0 name "value"` and `0 "name" "value"` parse as `KeyForm::ScriptString`, with the name stored as text.
- `map_text.cpp:439-442`: `KeyValueLine::name()` returns the raw key only for `Canonical`. A ScriptString key shows its literal name, never a KeyTable name.
- `src\qtapp\panels.cpp:443`: tooltip "script-string key (0 name "value")".

### 4.3 Does it matter? (UNVERIFIED)

- `all_modes` and `dom` look like gametype include and exclude flags on one struct. `dom 0` would then keep the struct out of Domination. Not confirmed by script text.
- Round trip: the editor keeps the original line text unless the value is set (`map_text.cpp:179-185`, `set()` at about line 432 rebuilds with the same prefix), so the form survives an edit.
- Recommendation: add `all_modes` and `dom` to the defs for `script_struct` (type bool, default empty, note "script-string key, written as `0 "name" "value"`"), and `tu0bakechanges` to worldspawn. Do not convert them to canonical ids.
